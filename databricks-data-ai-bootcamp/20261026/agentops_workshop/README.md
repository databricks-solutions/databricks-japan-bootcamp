# AgentOps ワークショップ（60分）: 修理受付の回答支援エージェント

家電メーカー（架空のブリックス電機）のコールセンターで、オペレーターを支援するエージェントを題材に、
**データの準備 → エージェント → オフライン評価 → 改善 → 再評価 → Databricks Apps へのデプロイ → 本番のトレース** までを、ブラウザだけで一通り体験します。

## 参加者の手順

1. このフォルダ（`agentops_workshop/`）を、ワークスペースの自分のフォルダにインポートする
2. `00_設定` の `CATALOG` を、使うカタログの名前に書き換える（なければ `01_準備` の実行時に作る）
3. `01` から順に、ノートブックを上から実行する（サーバーレスのコンピュート、環境のバージョン 4 以上）

| 順番 | ノートブック | やること | 時間 |
|---|---|---|---|
| 1 | `00_設定`・`01_準備` | **最初に実行する**。`CATALOG` を書き換え、AI Search のエンドポイントの用意と立ち上げの開始、データ（PDF・CSV）の配置、モデル・AI関数の確認 | 約5分 |
| 2 | `02_概要` | 説明（シナリオ・作るエージェント・データ・アーキテクチャ・流れ）。このあいだに AI Search の立ち上げが進む | 約20分 |
| 3 | `03_データパイプライン` | PDF のパース・チャンク分割（素の結果 → 型番の取り出し）・個人情報のマスク、検索インデックス（文書は画面で、過去事例はコードで作る）、UC関数 | 約12分 |
| 4 | `04_エージェント` | アプリの作成を始める。エージェントのコードを読み、1件動かしてトレースを見る | 約6分 |
| 5 | `05_評価` | 初版を評価 → 落ちたケースの理由とトレースを見る → Genie Code で評価結果を分析し、改善案を出させる | 約10分 |
| 6 | `06_改善` | 改善版の変更点を見る → 同じ評価データで評価して初版と比べる | 約10分 |
| 7 | `07_デプロイと監視` | 改善版をアプリにデプロイ → チャット画面で使う → 本番のトレースを見る | 約12分 |
| 終わったら | `99_クリーンアップ` | 自分が作ったものを削除する | ― |

- 準備も参加者が行います（講師が参加者ごとに用意するものはありません）
- PAT や API キーは使いません（ノートブックは実行している人、アプリはアプリのサービスプリンシパルの権限で動きます）
- 名前（スキーマ `agentops_<ユーザー名>`・アプリ `agentops-<ユーザー名>`）にはユーザー名が付くので、同じワークスペースを複数人で使えます。AI Search のエンドポイント（`bootcamp`）は共有します（インデックスは参加者ごと）

**時間の注意**: AI Search のエンドポイントを新しく作ったワークスペースでは、最初のインデックスの準備に約20分かかります（実測 21.5分）。そのため、**`01_準備` をハンズオンの最初に実行し、説明（約20分）を聞いているあいだに立ち上げを進めます**。説明のあとに `03_データパイプライン` を始めれば、インデックスの作成で待ちません。

## フォルダの構成

| パス | 内容 |
|---|---|
| `00_設定`〜`07_…`・`99_…` | 参加者のノートブック |
| `app/agent_v1.py`・`app/agent_v2.py` | 初版・改善版のエージェント（LangGraph）。違いはシステムプロンプトと検索の絞り込みの2か所 |
| `app/tools.py` | ツール（UC関数を MCP で呼ぶ製品情報の照会、AI Search の検索）と共通の部品 |
| `app/agent/`・`app/runtime/`・`app/ui/` | アプリのサーバー（AgentKit の `DurableAgentServer`）とチャット画面。`agentbricks init --framework langgraph` のひな形をもとにしている（Agent Bricks の CLI は使わない） |
| `app/app.yaml`・`app/requirements.txt` | アプリの起動のしかたと、使うパッケージ |
| `evaluation.py`・`data/eval_cases.json` | 評価データ（20件。60分版では10件）と採点器 |
| `apps_helper.py` | アプリの作成・デプロイ（Databricks SDK。CLI 不要） |
| `diagrams.py` | ノートブックに表示する図（`02` の概要、`03` のデータ処理の流れ） |
| `source/` | 同梱のデータ（PDF・CSV）。`01_準備` が Volume とテーブルに置く |

**ノートブックで評価したエージェントのコード（`app/agent_v2.py`）を、そのままアプリとしてデプロイします。** ノートブックとアプリで、別々のエージェントを作ることはしません。

## ワークスペースの前提（管理者に確認すること）

- 参加者がカタログを作れる（または、使うカタログがあり、参加者に `USE CATALOG`・`CREATE SCHEMA` が付いている）
- **Previews** で「AI Prep Search」が有効（`ai_prep_search` に必要）
- Genie Code が使える（`05_評価` の最後で評価結果の分析に使う。アカウントとワークスペースの両方で「Partner-powered AI features」が有効）
- モデル `databricks-claude-sonnet-5-5`・`databricks-claude-sonnet-4-5`・`databricks-qwen3-embedding-0-6b` が使える（`01_準備` で確認できる）
- SQL ウェアハウスが1つ以上あり、参加者が使える（トレースを読むのに使う。「Serverless Starter Warehouse」で可）
- アプリから PyPI に接続できる（アプリの起動時にパッケージを入れる）

## 仕組みのポイント

- **トレースは Unity Catalog に保存**します（`00_設定` の `use_experiment()` が、実験をトレースのテーブル `<スキーマ>.agent_otel_*` と結びつけて作る）。ノートブック・評価・アプリのトレースが、すべて同じ実験に入ります
- **アプリの権限**は、アプリのリソース（モデル・実験・インデックス・UC関数・トレースのテーブル）として宣言します。宣言すると、アプリのサービスプリンシパルに、親のカタログ・スキーマの `USE` も含めて自動で付きます
- アプリのサーバーは、Agent Bricks の CLI を使わずにデプロイするので、実行の状態はプロセスの中に持ちます（`DATABRICKS_AGENTBRICKS_RUNTIME_STORE_LOCAL=true`）

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| `00_設定` で「CATALOG に…入れてください」 | `CATALOG` を書き換える |
| `00_設定` で「カタログ…がなく、作る権限もありません」 | 管理者に、カタログの作成と権限の付与を依頼する |
| 03 のインデックスの作成が終わらない | エンドポイントの初回の立ち上げ中（約20分）。そのまま待つ |
| 03 の 4-3 で「…がまだありません」 | 文書のインデックスを、4-1 の手順で画面から作る。うまくいかなければ `CREATE_DOC_INDEX_BY_CODE = True` にして実行する |
| 03 のインデックスの作成で権限のエラー | 共有のエンドポイントに `CAN USE` がない → エンドポイントを作った人か管理者に付けてもらう |
| 01・03 の `ai_prep_search` で `PERMISSION_DENIED` | Previews の「AI Prep Search」が無効 → 管理者が有効にする |
| `use_experiment()` で「SQL ウェアハウスがありません」 | 管理者に、SQL ウェアハウスと `CAN USE` の付与を依頼する |
| 評価が10分以上進まない | セルを止めて、もう一度実行する |
| 評価でツールのエラー（429 Too Many Requests） | 同時の呼び出しが多すぎる。`MLFLOW_GENAI_EVAL_MAX_WORKERS` を小さくする（既定 4） |
| アプリのデプロイで「compute is in STARTING state」 | アプリの起動中。数分待って、もう一度実行する |
| アプリのチャット画面で回答が返らない | Compute → Apps → アプリ → Logs で、起動時のエラーを見る |
