# Genie Code による SQL 移行ハンズオン

ブラウザ上の Genie Code を使って、T-SQL を Databricks SQL に変換し、差分レビューと結果検証まで体験する。所要時間は **30分**。Lakebridge CLI や外部コーディングエージェントのインストールは不要で、このシナリオだけでも実施できる。

## ゴール

- 入力 SQL、移行先、出力先を指定して変換を開始できる。
- 変換成功の表示に加えて、実行結果が業務ルールに合うかを確認できる。
- 差分が出たとき、期待結果と実際の結果を示して修正・再検証を依頼できる。

## 事前準備

管理者・講師は開始前に、参加者が使うワークスペースで次を確認する。

1. Genie Code を利用できること。
2. 管理者が **Previews** で **agentic code converter (Beta)** を有効化していること。
3. 自分用の Workspace フォルダにファイルを読み書きできること。
4. SQL を実行する SQL Warehouse と、その利用権限があること。開始前に起動しておく。
5. 講師が本手順を同じ環境でリハーサルし、変換と結果検証まで完了できること。

機能要件・最新の画面手順は [公式ドキュメント: Convert SQL with the agentic code converter](https://docs.databricks.com/aws/en/migration/agentic-code-converter) を参照する。画面表示や機能提供状況は環境により異なる。

## 30分の進め方

| 経過 | 内容 | 到達点 |
|---|---|---|
| 0〜5分 | 入力ファイルの配置、業務ルール確認 | 入力と期待結果が分かる |
| 5〜15分 | Migration project で変換 | 変換後の SQL が生成される |
| 15〜25分 | 差分レビュー、実行、期待結果との比較 | 1本目の結果が一致する |
| 25〜30分 | 修正・再検証、振り返り | 残課題と完了条件を説明できる |

必須は1本目。早く終わった場合に2本目へ進む。

## 使用するファイル

| ファイル | 内容 |
|---|---|
| [input/01_top_customers.sql](input/01_top_customers.sql) | T-SQL。月次売上の上位3顧客。`TOP`、`ISNULL`、`CONVERT`、`DATEADD` を含む |
| [input/02_latest_order.sql](input/02_latest_order.sql) | 追加演習。顧客ごとの最終注文。`ROW_NUMBER`、`EOMONTH` を含む |
| [expected/01_top_customers.csv](expected/01_top_customers.csv) | 1本目の業務ルールから定めた期待結果 |
| [expected/02_latest_order.csv](expected/02_latest_order.csv) | 2本目の業務ルールから定めた期待結果 |

SQL 内に9件の架空データを埋め込んでいるため、SQL Server 接続やテーブル作成は不要。各 SQL は独立した SELECT クエリである。期待結果は変換ツールの参考出力ではなく、教材の正解データである。

## 1. 入力と業務ルールを確認する

Workspace に自分用の `agentic-migration` フォルダを作り、その下に `input` と `out` を作る。`input/01_top_customers.sql` を Workspace の `input` にアップロードする。Git folder にリポジトリを取得済みなら、その入力ファイルを使ってもよい。各参加者は自分の出力先を使う。

入力 SQL を開き、次の意味を確認する。

- 対象期間は **2026年7月1日以上、8月1日未満**。
- `completed` の注文だけが対象。`cancelled` は除外。
- 金額の NULL は0として扱う。
- 売上の降順で上位3顧客。同額の場合は `customer_id` の昇順。

期待結果は次の3行になる。

| customer_id | order_count | total_amount |
|---|---:|---:|
| B | 1 | 200.00 |
| A | 2 | 150.00 |
| D | 1 | 150.00 |

## 2. Migration project で変換する

公式Docsの「Convert existing SQL code」を開き、Workspace から **Migration project** を作成する。

| 設定 | 指定する値 |
|---|---|
| Name | 自分用の演習名 |
| Source dialect | T-SQL |
| Target framework | SQL |
| Destination folder | 手順1で作った自分用の `out` フォルダ |

**Add files** で1本目の入力を追加し、対象を選んで **Run** する。Genie Code の会話と出力ファイルを確認する。待ち時間には、どの関数・句が Databricks SQL で変わるかを予想する。

### 1ファイルを会話から変換する場合

Migration project を使わず、Genie Code の新しい会話で `/migrate` を入力して1本の SQL を指定する方法もある。入力・出力のパスは Workspace 上のファイルメニューからコピーし、実際の値に置き換える。

```text
/migrate
入力: <Workspace上のinput/01_top_customers.sqlのパス>
ソース方言: T-SQL
変換先: Databricks SQL
出力先: <自分用のWorkspace上のoutフォルダのパス>

入力ファイルを保持し、変換結果を出力先に保存してください。
SQL内の架空データと業務ルールを維持してください。
変更点と未検証の点を説明してください。
```

`/migrate` も同じ機能の利用要件を満たす必要がある。機能未有効時の代替手段ではない。

## 3. 差分レビューと結果検証を行う

変換後 SQL を開き、元の SQL と比較する。特に次を確認する。

1. `TOP (3)` の行数制限と並び順が維持されている。
2. 月初・月末の注文が含まれ、6月30日・8月1日が除外されている。
3. キャンセル除外、NULLの扱い、金額の小数精度が維持されている。
4. 入力の9件が勝手に削除・変更されていない。

差分を受け入れ、SQL Warehouse を選択してクエリ全体を実行する。出力ファイルを直接実行できない場合は、SQL editor の新しいクエリへ全文をコピーして実行する。

結果を [期待結果](expected/01_top_customers.csv) と照合する。3行あること、顧客の順番、件数、金額を確認する。`200` と `200.00` のような表示形式の違いは値として比較するが、金額が小数を保持できる型であることは別途確認する。

### エラーや不一致がある場合

実際のエラー全文、または実行結果を添えて次を依頼する。

```text
変換後のSQLを実行すると、以下のエラー／結果になりました。
<実際のエラー全文または結果>

期待結果は、B: 1件・200.00、A: 2件・150.00、D: 1件・150.00の順です。
対象は2026年7月のcompleted注文で、同額はcustomer_id昇順です。

元のSQL・入力データと比較して原因を特定し、出力側だけを修正してください。
期待結果を直接返すSQLや、入力データの変更で合わせないでください。
再実行し、件数・金額・順序を比較してください。
実行できない場合は、その理由と私が実行するSQLを示してください。
```

最初から一致した場合、故意に不具合を作る必要はない。次の追加演習か、境界条件のレビューに進む。

## 4. 追加演習: 顧客ごとの最終注文

`input/02_latest_order.sql` を同様に配置し、プロジェクトに追加して変換する。
月内の完了済み注文に絞った後、顧客ごとに日付が最新の注文を取得する。同日なら `order_id` が大きい方を採用する。

| customer_id | order_id | order_date | amount |
|---|---:|---|---:|
| A | 2 | 2026-07-15 | 50.00 |
| B | 3 | 2026-07-31 | 200.00 |
| C | 6 | 2026-07-10 | 80.00 |
| D | 7 | 2026-07-25 | 150.00 |

顧客 C で注文6が選ばれることを確認する。ウィンドウ関数の並び順から `order_id DESC` が欠けると、同日の選択が不定になる。

NULLの扱いをさらに検証するなら、入力のコピーで注文6の金額を NULL に変更し、変換後の C の金額が0になるか試す。元の入力と基準の期待結果は残し、変更したケースを別に記録する。

## 完了の確認

- 入力1本に対応する出力ファイルがある。
- 変換後 SQL を自分の環境で実行できた。
- 必須演習の3行が期待結果と一致した。
- 月の境界、キャンセル、同額の順序を確認した。

この演習は、小さなテストデータによる意味の確認までを扱う。移行案件では現行システムと同等の入力で現新比較を行い、データ量・性能・連携・運用も検証する。

## トラブルシュート

| 問題 | 原因 | 対処 |
|---|---|---|
| Migration project や `/migrate` が使えない | Beta機能の有効化、権限、環境要件が未充足の可能性 | 管理者が公式Docsの要件を確認する。当日は講師の有効な環境でのデモと差分・結果レビューに切り替える |
| 入力ファイルが見つからない | ローカルPCのパスを指定している、または権限がない | Workspaceに配置したファイルのパスと読み取り権限を確認する |
| 出力を保存できない | 出力先がない、または書き込み権限がない | 自分が書き込める `out` フォルダを作り直し、出力先を修正する |
| SQLを実行できない | Warehouse未選択・停止中・権限不足の可能性 | 実際のエラーを確認し、利用可能なWarehouseを選ぶ。必要なら講師へ連絡する |
| 変換に時間がかかる | 処理待ち、または自動修正が続いている | 会話と状態を確認し、まず1本目に集中する。残り10分で未完了なら講師のリハーサル結果を使って検証を進める |

## 講師向け: 当日までの確認

入力2本をSQLGlotでDatabricks SQLへ変換し、Serverless SQL Warehouseで実行して、期待結果の全行・値が一致することを確認済み（2026-09-10）。これはテストデータと期待結果の確認であり、Genie Codeによる変換の検証ではない。Genie Codeの画面操作から変換・レビュー・実行までの通しリハーサルは未完了。必ず当日環境で完了させる。

- 参加者と同等の権限で、入力1本目の配置から期待結果一致まで実行する。
- 待ち時間を計測し、30分に収まるか確認する。
- デモ用に実際の変換出力と実行結果を保存する。手書きのSQLをGenie Codeの出力例と呼ばない。
- 画面が公式Docsと異なる場合、当日の入口と操作を参加者へ案内する。
