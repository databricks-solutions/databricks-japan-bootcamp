# Lakeflow Designer ワークショップ — 顧客環境 事前準備ガイド(基盤管理者向け)

本ドキュメントは、Lakeflow Designer ワークショップを既存の Databricks ワークスペースで実施する場合に、ワークスペースの基盤管理者(Databricks Admin)が事前に行う準備作業をまとめたものです。

- **想定読者**: ワークスペース管理者 / メタストア管理者 / アカウント管理者
- **所要時間目安**: 30 分〜1 時間(全 8 ステップ)
- **実施タイミング**: ワークショップ実施日の 1〜2 営業日前 に完了を推奨

## 0. 前提条件・確認事項

開始前に以下を確認してください。

### 0.1 担当者の権限

- [ ] **アカウント管理者**: ユーザー招待・グループ作成
- [ ] **ワークスペース管理者**: SQL ウェアハウス作成、参加者のワークスペース権限管理
- [ ] **メタストア管理者** または `MANAGE CATALOG` 権限: カタログ作成・権限付与

担当者が複数に分かれる場合は、本ガイドの各ステップを担当者ごとに割り振ってください。

## 1. 参加者をワークスペースに招待

### 1.1 目的

ワークショップ参加者がワークスペースにログインできる状態にする。

### 1.2 操作手順

1. **アカウントコンソール**(https://accounts.cloud.databricks.com)にログイン
2. 左メニュー →「**ユーザー管理**」→「**ユーザー**」
3. 「**+ ユーザー追加**」をクリック
4. 参加者のメールアドレスを改行区切りで複数入力可能
5. 招待を送信
6. 招待された参加者は、メール内のリンクから初回ログイン

または、ワークスペース管理画面の「**設定**」→「**ユーザー管理**」からも追加可能(企業アカウントの SSO 連携状況に応じて使い分け)。

### 1.3 確認事項

- [ ] 全参加者が **ユーザー一覧** に表示される
- [ ] 各参加者の **ワークスペースアクセス** が有効化されている
- [ ] テスト用に 1 名にログインを依頼して、UI が表示されることを確認

## 2. ワークショップ参加者向けユーザーグループ作成

### 2.1 目的

参加者の権限を個別ではなくグループ単位で管理することで、後の権限付与作業を効率化する。

### 2.2 操作手順

1. ワークスペース左サイドバー →「**設定**」→「**Identity and access**」(または管理コンソールの「**グループ**」)
2. 「**+ グループ追加**」をクリック
3. グループ名:
   - **推奨**: `lakeflow_designer_workshop_participants`
   - もしくは社内命名規則に合わせて(例: `ws-lakeflow-yyyymm`)
4. 説明欄(任意): 「Lakeflow Designer ワークショップ参加者向けの一時的グループ」

### 2.3 確認事項

- [ ] グループが **グループ一覧** に表示される
- [ ] グループ作成日とオーナーを記録(削除時の参考用)

## 3. グループに参加者を追加

### 3.1 目的

ステップ 1 で招待した参加者をステップ 2 のグループに紐づける。

### 3.2 操作手順

1. ステップ 2 で作成したグループを開く
2. 「**メンバー**」タブ →「**+ メンバー追加**」
3. 参加者を検索 / 選択して一括追加
4. (任意)講師・サポート役の SA / DSA も追加すると、参加者と同じ視点で動作確認できる

### 3.3 確認事項

- [ ] 参加者全員がグループメンバーに追加されている
- [ ] グループメンバー数 = 参加者数(+ 講師数)

## 4. ワークショップ用 SQL ウェアハウス作成

### 4.1 目的

参加者が以下の操作で利用する SQL コンピュートを準備:

- Catalog Explorer での SQL クエリ実行
- AI/BI Dashboard のグラフ描画(モジュール M4)
- Genie Spaces の質問応答(モジュール M5)
- Lakeflow Designer のプレビュー実行

### 4.2 操作手順

1. ワークスペース左サイドバー →「**SQL ウェアハウス**」
2. 「**+ SQL ウェアハウスの作成**」
3. 推奨設定:

   | 項目 | 推奨値 | 備考 |
   |---|---|---|
   | 名前 | `lakeflow-workshop-warehouse` | 識別しやすい名前 |
   | クラスタサイズ | **X-Small** または **Small** | 参加者 ~20 名なら X-Small で十分 |
   | 自動停止 | **10 分** | コスト最適化 |
   | スケーリング(クラスタ数) | 最小 1 / 最大 4 | 同時利用に応じて拡張 |
   | ウェアハウスのタイプ | **サーバーレス** を強く推奨 | 起動が高速 |
   | チャネル | Current(推奨) | |

4. 「**作成**」をクリック
5. 作成後、状態が **実行中** または **停止中** になっていることを確認

### 4.3 確認事項

- [ ] ウェアハウスが一覧に表示される
- [ ] 手動で一度起動して、`SELECT 1` が実行できることを確認
- [ ] ウェアハウス ID を控えておく(必要に応じて講師に共有)

---

## 5. SQL ウェアハウスの使用権限をグループに付与

### 5.1 目的

参加者(ステップ 2 のグループ)がステップ 4 のウェアハウスを起動・利用できるようにする。

### 5.2 操作手順

1. ステップ 4 で作成した SQL ウェアハウスを開く
2. 右上の「**︙(メニュー)**」または「**権限**」をクリック
3. 「**権限を編集**」または「**+ 権限を追加**」
4. ステップ 2 で作成したグループ(`lakeflow_designer_workshop_participants` 等)を選択
5. 権限レベル: **CAN USE**(使用可能)を付与
6. 保存

### 5.3 確認事項

- [ ] グループに **CAN USE** 権限が付与されている
- [ ] 参加者 1 名でテストログインし、ウェアハウスが選択肢に表示されることを確認

## 6. ワークショップ用カタログ作成

### 6.1 目的

ワークショップで使用するテーブル・ボリュームを格納するための、専用 Unity Catalog カタログを作成する。

### 6.2 操作手順

1. ワークスペース左サイドバー →「**カタログ**」(Catalog Explorer)
2. 上部の「**+ カタログ作成**」または「**+ 新規**」→「**カタログ**」
3. 推奨設定:

   | 項目 | 推奨値 | 備考 |
   |---|---|---|
   | カタログ名 | `lakeflow_workshop` | 社内命名規則がある場合はそれに従う |
   | タイプ | **Managed**(マネージド) | デフォルトでよい |
   | コメント | `Lakeflow Designer ワークショップ用` | 識別子として |
   | ストレージロケーション | (デフォルトで OK) | メタストアデフォルトを使用 |

4. 「**作成**」をクリック

### 6.3 確認事項

- [ ] カタログ一覧に新しいカタログが表示される
- [ ] カタログ名を講師と参加者に共有(サンプルデータ生成 Notebook のウィジェットで指定するため)

> **重要**: このカタログ名はサンプルデータ生成 Notebook のウィジェット「**1. カタログ名(必須)**」に入力する値です。**講師にも共有してください**。

---

## 7. カタログに ALL PRIVILEGES をグループに付与

### 7.1 目的

参加者が以下のすべてをカタログ内で自由に実行できるようにする:

- スキーマ・テーブル・ボリュームの作成 / 読み取り / 書き込み / 削除
- パイプライン実行によるテーブル生成
- Excel ファイルの UC テーブルへの昇格(Module 2)

### 7.2 操作手順

1. ステップ 6 で作成したカタログを開く
2. 上部の「**権限**」タブ
3. 「**+ 権限を付与**」
4. プリンシパル: ステップ 2 で作成したグループ(`lakeflow_designer_workshop_participants` 等)を選択
5. 権限: **ALL PRIVILEGES** を選択
6. 「**付与**」をクリック

### 7.3 確認事項

- [ ] グループに **ALL PRIVILEGES** が付与されている
- [ ] 参加者 1 名で `CREATE SCHEMA <カタログ名>.test_schema` が実行できることを確認

### 7.4 (参考)SQL での同等操作

UI ではなく SQL で実行する場合:

```sql
GRANT ALL PRIVILEGES
  ON CATALOG <カタログ名>
  TO `lakeflow_designer_workshop_participants`;
```

## 8. サンプルデータ生成 Notebook の実行

### 8.1 目的

ワークショップで使うサンプルデータ(顧客・商品・売上トランザクション・Excel ファイル)を、ステップ 6 で作成したカタログに事前生成する。

### 8.2 事前確認

- [ ] ステップ 6 のカタログ名 をメモしておく
- [ ] 参加者または管理者がアクセス可能なコンピュート(汎用クラスタまたはサーバーレス)が用意されている

### 8.3 操作手順

1. 本リポジトリの [`notebook/01_generate_workshop_data.py`](./notebook/01_generate_workshop_data.py) をワークスペースにインポート
   - **インポート手順**: ワークスペース内の任意のフォルダで右クリック →「**インポート**」→ ファイル選択
2. Notebook を開く
3. **「2. パラメータ設定(ウィジェット)」のセルまでを実行**(Cell 上部の「▶ Run cell」ボタン または `Shift + Enter`)
4. 画面上部にウィジェットが表示されることを確認
5. 「**1. カタログ名(必須)**」にステップ 6 で作成したカタログ名(例: `lakeflow_workshop`)を入力
   - その他のウィジェット項目はデフォルトのままで OK
6. 「**Run all**」(全セル実行)をクリック
7. 全セル正常完了を待つ(数分〜10 分程度)

### 8.4 確認事項

- [ ] Notebook の最終セル「Workshop data generation completed.」が出力される
- [ ] Catalog Explorer で次のテーブルが生成されたことを確認:
  - `<カタログ名>.lakeflow_designer_workshop.customer_master`(5,000 行)
  - `<カタログ名>.lakeflow_designer_workshop.product_master`(500 行)
  - `<カタログ名>.lakeflow_designer_workshop.sales_transactions`(~50,000 行)
- [ ] ボリューム `<カタログ名>.lakeflow_designer_workshop.workshop_files` 配下に `segment_targets.xlsx` が存在することを確認

### 8.5 (Module 2 採用時)Excel ファイルの事前配布

Module 2 を採用する場合、サンプルデータ生成 Notebook 実行後に UC Volume 上に生成された Excel ファイル `segment_targets.xlsx` を、**ワークショップ実施前に参加者へ配布**しておく必要があります(Module 2 Step 2-3 で参加者が自身の PC からアップロードする想定のため)。

#### 8.5.1 配布の流れ

1. ステップ 8 完了後、Catalog Explorer で `<カタログ名>.lakeflow_designer_workshop.workshop_files` ボリュームを開く
2. `segment_targets.xlsx` をローカル PC にダウンロード(右クリック →「ダウンロード」など)
3. メール、Slack、社内共有フォルダなどで参加者全員に配布

#### 8.5.2 配布タイミング

ワークショップ実施日の **前日まで** に参加者の手元へ届くようにする。

#### 8.5.3 確認事項

- [ ] 参加者全員が `segment_targets.xlsx` を受領済み
- [ ] ファイルサイズが概ね 7KB 程度(壊れていないことを確認)

### 8.6 トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| `ValueError: ウィジェット「1. カタログ名(必須)」が空です` | ウィジェットが未入力のまま実行された。ステップ 8.3 の手順 5 を実施 |
| `Permission denied`(カタログ書き込み) | ステップ 7 の権限付与漏れ。`ALL PRIVILEGES` を再確認 |
| `dbldatagen` / `openpyxl` のインストール失敗 | コンピュートのネットワーク制限。社内プロキシ経由なら pip プロキシ設定が必要 |
| `segment_targets already exists` エラー | 過去ランの残骸。SQL で `DROP TABLE <カタログ名>.lakeflow_designer_workshop.segment_targets;` |
| Notebook が起動しない | 汎用クラスタが停止中、もしくはサーバーレスが無効。担当者に確認 |

## 10. ワークショップ実施後のクリーンアップ

ワークショップ終了後、不要なリソースを停止・削除します。

### ステップ A: 誤ってスケジュール実行を設定した参加者ジョブの削除

参加者には **ワークショップ中、Module 1 の Step 1-9(Lakeflow Jobs スケジュール設定)については UI の確認のみで実際にはスケジュールを設定しないよう案内**しています。

ただし、誤ってスケジュール実行を有効化したまま終了した参加者がいた場合、放置すると毎日 DBU が発生し続けるため、該当ジョブは必ず削除してください。

- ワークスペースの「**ワークフロー**」「**ジョブ**」一覧を確認し、参加者作成のジョブにスケジュールが残っていないかチェック
- 残っている場合は、業務本番ジョブを誤って消さないよう個別に確認しながら削除

### ステップ B: SQL ウェアハウスの停止または削除

1. ワークスペース →「**SQL ウェアハウス**」
2. ステップ 4 で作成したワークショップ用ウェアハウスを選択
3. 「**停止**」(再利用予定がある場合)または「**削除**」(再利用予定がない場合)

### ステップ C: カタログの削除(任意)

ワークショップ用カタログを完全に削除する場合(データを残す必要がなければ):

```sql
DROP CATALOG IF EXISTS <カタログ名> CASCADE;
```

データを残してアーカイブしたい場合は、カタログをそのまま残すか、別カタログに移管。

### ステップ D: ユーザーグループの整理(任意)

- **一時利用**: グループ削除
- **継続利用**: グループ名を変更して使い回し(例: `lakeflow_designer_workshop_archive_2026Q2`)

### クリーンアップ完了チェックリスト

- [ ] **ステップ A**: 参加者が誤って設定したスケジュールジョブを個別確認・削除
- [ ] **ステップ B**: SQL ウェアハウスを停止または削除
- [ ] **ステップ C**: カタログを削除またはアーカイブ(任意)
- [ ] **ステップ D**: ユーザーグループを整理(任意)
